# 첫 실행 체크리스트

VoidLight CoDesign을 처음 실행한 뒤 아래 항목을 순서대로 확인한다.

## 1. 앱 실행

- [ ] 앱 이름이 `VoidLight CoDesign` 또는 `VoidLight 코디자인`으로 표시된다.
- [ ] About 또는 안내 문구에서 Open CoDesign 기반 fork임을 확인할 수 있다.
- [ ] MIT license 및 OpenCoworkAI credit이 유지된다.
- [ ] unsigned alpha 경고를 읽고 테스트 환경에서 실행 중임을 확인했다.

## 2. 한국어 UI

- [ ] 주요 온보딩과 설정 화면이 한국어로 표시된다.
- [ ] 입력창에서 한글 IME 조합 입력이 깨지지 않는다.
- [ ] 용어가 문서와 크게 다르지 않다. 예: Provider, Model, Generate, Export.

## 3. Provider 선택

둘 중 하나를 선택한다.

### official API key

- [ ] official API key를 준비했다.
- [ ] 비용과 rate limit을 이해했다.
- [ ] key가 평문 파일이나 로그에 저장되지 않는지 확인한다.
- [ ] 연결 테스트가 성공한다.

### VibeProxy/CLIProxyAPI experimental

- [ ] VibeProxy를 사용자가 별도로 설치했다.
- [ ] 기본 local proxy 감지는 `127.0.0.1:8317/8318` 계열을 기준으로 하며, 커스텀 포트 사용 시 별도 확인이 필요하다는 점을 이해했다.
- [ ] provider ToS 및 계정 정책 리스크를 확인했다.
- [ ] 자동 기동이 아니라 명시적으로 실행했다.
- [ ] 실패 시 official API key fallback으로 전환할 수 있다.

## 4. 첫 데모 생성

- [ ] 간단한 한국어 프롬프트를 입력한다.
- [ ] 결과가 생성된다.
- [ ] 오류가 발생하면 provider 오류인지, 앱 오류인지 구분해 기록한다.
- [ ] crash가 발생하면 로그에 prompt, token, account email이 포함되지 않는지 확인 후 공유한다.

## 5. 피드백 제출 전 기록

- macOS 버전
- 설치 방식: Homebrew Cask PoC / 수동 설치
- 앱 채널: `alpha-ko`
- provider 방식: official API key / VibeProxy
- 성공 또는 실패 단계
- 재현 가능한 오류 메시지

## 완료 기준

테스터가 문서만 보고 설치, 첫 실행, provider 연결, 첫 데모 생성까지 도달하면 M3 목표를 만족한다.
