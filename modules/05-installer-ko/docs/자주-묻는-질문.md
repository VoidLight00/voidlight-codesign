# 자주 묻는 질문

## 이 앱은 Open CoDesign인가요?

VoidLight CoDesign은 OpenCoworkAI의 Open CoDesign을 기반으로 한 한국어 fork다. 원 저작권과 MIT 라이선스 표기는 유지한다.

## 알파 빌드를 일반 작업에 사용해도 되나요?

권장하지 않는다. `v0.1.4-ko-alpha`는 개발자 프리뷰이며 unsigned/dev build일 수 있다. 중요한 작업에는 안정 채널을 기다리는 것이 좋다.

## macOS에서 앱이 차단됩니다.

알파 빌드는 서명 및 공증이 완료되지 않았을 수 있다. `시스템 설정 → 개인정보 보호 및 보안`에서 직접 허용할 수 있다. `xattr` 격리 해제는 알파 테스트용 최후 수단이며 v1.0 정책이 아니다.

## 어떤 provider 연결 방식을 써야 하나요?

가능하면 official API key 방식을 먼저 권장한다. 비용과 약관이 명확하고 fallback 경로로 계속 지원된다. VibeProxy/CLIProxyAPI는 experimental이며 provider ToS 및 계정 정책 리스크가 있을 수 있다.

## VibeProxy가 자동으로 감지되지 않습니다.

다음을 확인한다.

- VibeProxy가 실행 중인지 확인
- 기본 local proxy 후보 `8317/8318` 또는 사용자 지정 포트가 다른 앱과 충돌하지 않는지 확인
- 방화벽 또는 프록시 설정 확인
- 실패하면 official API key 방식으로 전환

## API key를 앱에 넣어도 안전한가요?

알파 단계에서는 token/API key 평문 저장 금지가 원칙이다. key가 로그, crash report, 일반 텍스트 설정 파일에 남는지 확인하고 문제가 있으면 즉시 보고한다.

## Homebrew Cask가 실패합니다.

현재 Cask는 PoC 초안이다. 릴리스 URL, SHA, 버전이 아직 확정되지 않았을 수 있다. 실패하면 수동 설치로 진행하고 오류 메시지를 기록한다.

## 자동 업데이트가 되나요?

`alpha-ko` 채널은 자동 업데이트를 기본 제공하지 않는다. 릴리스 노트와 설치 문서에 따라 수동 업데이트한다.

## 회사나 강의 환경에서 써도 되나요?

상업적·대규모 사용 전 provider ToS, 개인정보 처리, 보안 정책을 반드시 확인해야 한다. 특히 VibeProxy 경로는 experimental로만 취급한다.

## 문제가 생기면 무엇을 보내야 하나요?

- macOS 버전
- 설치 방식
- 앱 채널
- provider 방식
- 재현 단계
- 오류 메시지

단, API key, OAuth token, 계정 이메일, 민감한 prompt는 공유하지 않는다.
